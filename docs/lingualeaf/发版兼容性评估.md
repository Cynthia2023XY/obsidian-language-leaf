# 主词库归属调整的发版兼容性评估

评估日期：2026-11-14。本次只提交代码和评估，不创建 Release，不修改版本号。

## 结论

以已发布 0.5.0 为升级基线，普通单笔记库用户的数据位置保持不变，不会自动创建库外数据源，不会被连接到开发者的 Cynthia Note，也不会自动迁移到新主词库格式。

但不能将“路径兼容”扩大为“所有功能均零风险”：本轮累计架构改造包含共用复习流程、阅读选区和词典异步逻辑，仍应通过发版后的实际升级冒烟验证。当前测试提供兼容性证据，不代替所有用户环境验收。

## 普通用户默认行为

已发布 0.5.0 的普通学习设置不包含 `libraryPath`、`libraryMode`、`libraryId`。

1. `readSettings()` 将数据目录保留为当前库内的 `LinguaLeafData`，连接路径为空，连接模式不设置。
2. `resolveLibraryDirectory()` 返回未配置独立学习库。
3. `LeafHost` 继续选择当前 Vault 的 `VaultPort` 与 `LegacyLearningAdapter`。
4. 词句资料仍通过原 Markdown 卡片和库内词条快照索引；复习事件仍保存在当前库 `LinguaLeafData/review/events/`。
5. 没有主词库配置时，启动流程不会保存独立库 ID，不会调用迁移服务，不会访问本机外部绑定文件。
6. 创建、连接和移动独立词库均需显式操作。迁移命令不是插件启动流程的一部分，也不随 Release 附件自动执行。

因此普通用户原本同步整个笔记库的方式继续覆盖其原有学习数据。默认路径兼容不代表插件会自动替他创建 `LanguageLeafLibrary`；这种新模式需要主动创建、迁移或连接。

## 不同用户群体的影响

| 场景 | 升级后的行为与注意点 |
| --- | --- |
| 普通单库，使用已发布 0.5.0 默认配置 | 保留随文卡片与库内 LinguaLeafData，无强制迁移。 |
| 主动启用库内独立词库 | 主库相对路径随当前笔记库解析；评分权威历史仍在库内，本机锁、缓存和会话放在库外。切换设备仍需先同步。 |
| 已经设置旧版绝对 libraryPath | 继续识别旧连接；不会自动移动目录。旧库升级到 schema 3 后，旧插件不能继续读取，需让所有窗口使用新版。 |
| 外部入口在另一台设备使用 | 只同步学习库 ID，本机绝对地址不传播。该设备需先下载主库，再明确绑定当地路径；未绑定时可打开设置，但学习写入明确失败，不创建空替代库。 |
| 两台设备离线同时改同一独立词库 | 尚不支持自动业务冲突合并，不能作为已完成能力宣传。 |
| 手机或平板 | 本次没有移动端适配，manifest 仍为 desktop only。 |

本次将词库移动到 Cynthia Note 的操作仅应用于用户当前机器上明确指定的两个笔记库。运行时连接解析没有写死开发者的电脑绝对路径；缺失外部连接的提示已改为通用“主笔记库”。

## 发版建议

可作为可选独立词库功能更新交付，但不应承诺升级自动迁移所有用户，或已支持任意跨设备离线并发。

发布说明应明确：旧用户默认保留库内数据；独立主词库为手动启用；启用后的旧版本回退有限制；跨设备使用先同步，外部入口按设备配置地址。实际发布时递增版本号，不覆盖已发布 0.5.0 的资产。

目前只在本机正式库验证过独立主库复习及一次现有 Remotely Save 同步；未完成另一台真实设备下载验收，也未逐一验证所有第三方同步工具和较旧 Obsidian 版本。

# Language Leaf 自建复习器技术方案

日期：2026-10-26。状态：设计提案，未接入生产代码，未迁移任何卡片或复习进度。

## 1. 决策

采用「自有复习界面 + 自有会话与持久化 + 独立 FSRS 算法库」。不调用 Spaced Repetition 插件的内部对象，不要求用户安装或启用该插件，不自行重写 FSRS 数学模型。

优先对 `ts-fsrs@5.4.1` 做兼容性验证并精确锁版。它是上游当前 package.json 明确锁定的版本；该包的算法模型是 FSRS-6，而不是“FSRS-5”。库版本和算法模型版本分开记录。v5.4.1 包声明 Node >=20，v6 当前声明 >=24；这些是包的支持条件，不能直接推断 Obsidian 的实际运行环境已经满足。

本项目仍使用 TypeScript 4.4.4、esbuild 0.13.12。接入前在隔离测试工程中验证声明文件、打包产物和 Obsidian/Electron 中的实际加载；如需更新构建工具，单独执行并回归现有 Vue 面板。保留 MIT 许可证和必要署名。首版只用调度库，不引入参数训练、Rust/WASM 或原生扩展。

## 3. 第一版产品范围

支持英文/法语词句、单向回忆、显示答案、四档评分、新卡/到期卡/短期重学、撤销最近一次评分、发音、暂停、当场编辑、返回原文和关闭后恢复。

先保持现有粒度：一张来源语境卡对应一份复习进度。跨文章同词不自动合并；expressionId 用来关联例句和统计，不作为唯一评分 ID。未来反向题和填空题是同一内容派生的独立 reviewCardId，各自保存进度。

新增独立的内置复习预览命令。既有安装维持 SR 行为；启用内置引擎只影响明确选择的新卡或完成迁移的卡片，不能用一个全局开关自动接管所有旧卡。现有 owner 硬编码和校验必须通过版本化适配修改，不能只增加弹窗而绕开归属检查。

首版不做图片遮挡、自动参数训练、跨设备实时协同、任意 SR 卡型或无损双向引擎切换。可在同一 Vault 中共存，但同一张卡只能由一个引擎负责调度。

## 4. 模块结构

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| ContentRepository | 按稳定 cardId 读取词句、语境与来源，订阅内容变化 | 计算到期时间 |
| FsrsAdapter | 创建新状态、预览四档结果、处理评分 | 打开弹窗、写磁盘 |
| ReviewQueue | 到期排序、每日新卡限额、短期等待、跳过 | FSRS 数学计算 |
| ReviewService | 唯一评分提交入口、版本校验、幂等、撤销、会话恢复 | DOM 操作 |
| ReviewStore | 不可变评分记录、状态缓存、配置版本、冲突检测 | 修改原文释义 |
| ReviewModal | 题面/答案/编辑/保存失败/等待/完成状态 | 直接调用磁盘或算法库 |
| SrImportAdapter | 识别旧注释、生成迁移预览和备份 | 自动迁移整个 Vault |

通过接口与 Vault、日期、音频和界面解耦。复用现有 FilePort/来源定位及 Vue 面板能力，但复习界面只读取结构化字段，不解析“原句：”等展示标签。

## 5. 数据依据与结构

当前文章中的可见卡片内容仍作为内容依据；已有 JSON 是快照和操作记录，不在第一版另建一份可独立修改的词句数据库。内置复习状态和评分历史独立保存在 Vault 的 LinguaLeafData/review 下，插件 data.json 只保存设置。

- ReviewCard：reviewCardId、sourceCardId、expressionId、题型、enabled/suspended、sourceRevision。
- ScheduleSnapshot：schema、reviewCardId、revision、algorithm=fsrs、libraryVersion、modelVersion、parameterVersion、due、stability、difficulty、elapsed_days、scheduled_days、learning_steps、reps、lapses、state、last_review。
- ReviewEvent：operationId、reviewCardId、expectedRevision、rating、reviewedAt、before、after、算法日志、parameterVersion、sessionId。
- UndoEvent：operationId、撤销的评分事件 ID、预期最新版本、恢复后的状态。作为补偿事件，不删除旧日志。
- SessionCheckpoint：队列、当前位置、已完成卡 ID、学习中卡 ID；不保存为“已评分”直到评分事件成功落盘。

建议布局：review/cards/<id>.json 存绑定；review/events/<operationId>.json 存提交记录；review/state/<id>.json 存可重建缓存；review/parameters/<version>.json 存算法参数；review/sessions/<id>.json 存会话检查点。目录与文件均显式 schema 化。

所有时间持久化为 UTC ISO 字符串，传给 FSRS 时恢复 Date。到期判断按时间戳；每日新卡限额按配置时区与日界线计算。默认日界线 04:00，可配置；不因为时区变化改写已保存 due。

文件重命名跟随 cardId 重新解析来源。来源被删除时暂停或标记失联，不悄悄删除复习历史。检测到重复 cardId 时阻止评分，要求先解决身份冲突。

## 6. FSRS 接入

v5.4.1 适配使用 createEmptyCard(now)、fsrs(parameters)、repeat(card, now)、next(card, now, grade)。固定且可注入 Clock；测试固定随机种子。

初始建议：目标保留率 0.9、enable_short_term=true、学习步骤 1m/10m、重学步骤 10m；这些属于可配置起点，不是对任何用户记忆效果的承诺。最大间隔使用固定配置，并把完整参数连同版本保存。最初不训练个人参数。

新卡 → Learning → Review；忘记后可能进入 Relearning，具体状态转换由库决定。

一次答案揭晓创建 PreparedReview：卡片版本、统一时间、参数版本和四档候选结果。评分按钮展示这些候选 due 的相对间隔；选档时提交同一候选，不另起一个随机计算产生不同间隔。若卡片版本变化或上下文过期，则刷新预览并提示。记录实际点击时间与调度计算时间，避免混淆。

UI 使用“不记得/较难/记得/简单”映射 Again/Hard/Good/Easy。间隔从候选状态计算，不能在实际插件里写死。数字键 1—4 在揭晓答案后才生效；输入框编辑、输入法组合状态和保存期间均不接收评分。

## 7. 队列和短期学习

优先顺序：到期的学习/重学卡 → 到期复习卡 → 每日限额内的新卡。首版默认每日新卡 10 张、到期复习不限额，用户可调整。按文章/标签筛选只改变本次队列，不重置卡的进度。

未到期的短期卡进入等待队列，绝不提前当成到期卡反复弹出。其他卡用完后显示“下一张将在…后到期”，可结束本次或等待；等待时监听时钟，关闭应用不把等待算作完成。

统计区分“已完成卡”“学习中”“本次评分次数”。Again 导致重学时不能把卡数越评越少、又悄悄加回而不解释。跳过不写评分、不改变 due，只影响本次会话。暂停是持久化状态，需要可恢复。

同一来源以后生成多个题型时，另做关联卡避让策略，防止刚看过答案立刻考反向题；第一版单向题不实现复杂的 sibling 机制。

## 8. 提交、失败恢复和撤销

评分顺序：锁定当前卡 → 校验 cardId/revision/内容来源 → 创建一次 operationId → 保存不可变 ReviewEvent → 更新缓存和会话检查点 → 成功后推进队列。

双击、长按和失败重试复用同一次操作身份，不能累计评分次数。界面只有保存成功才换卡；失败时保留当前答案和重试入口。关闭窗口不会重新打开已关闭的窗口，已经成功落盘的评分仍保留。

一个评分事件包含 before/after 和版本，作为恢复依据。事件写成功但缓存未更新时，重启重放已提交事件；不存在提交事件的操作不算评分成功。不能把多文件写入声称为数据库事务，缓存和检查点必须允许重建。

同一进程内按卡串行提交，窗口通过同一个 ReviewService 交互。若同步或其他实例产生同版本分叉，保留事件并停止自动合并，不能用“最后写入覆盖”隐瞒丢失。首版不承诺多设备同时评分后自动合并。

撤销只处理最近一笔、且未被后续操作覆盖的有效评分；写补偿事件并恢复卡状态和会话位置。库的 rollback 是计算工具，不代替保存与队列恢复。

## 9. 旧卡迁移与调度归属

迁移先只读扫描，生成清单：内容卡数、引擎、是否有完整 FSRS 状态、是否只有旧 SM-2 注释、重复或损坏卡片、预期处理。

- 未评分卡：可创建新 FSRS 状态。
- 有完整 FSRS 注释：逐字段验证、记录来源算法/库版本；兼容性验证后导入状态，不伪造缺失日志。
- 只有 SM-2 的 due/interval/ease：允许选择“近似转换并尽量保留首次到期时间”或“保留内容、作为新卡开始”。明确标记近似来源和估算字段，不能称无损迁移。
- 损坏或重复卡：保持原样，列入待处理，不自动猜测。

迁移必须保存原文件和原 SR 注释备份，有逐卡操作日志与恢复入口。先关闭 SR 复习窗口。

注意：只把 metadata.owner 改为 builtin 并不能让 SR 停止识别原来的 ? 分隔符。需要为内置卡使用新的内容块版本，并逐卡移除/替换 SR 可识别的问答分隔符；保留词句、原文、译文和定位标记。混合笔记不能直接删除整篇的 #flashcards 标签，避免停掉其他仍交给 SR 的卡片。

迁移事务有 prepared/source-converted/verified/active 阶段。解除 SR 识别并复验队列后才启用内置评分；中断时根据备份和日志继续或回滚。旧引擎和内置引擎不得同时推进同一张卡。内置评分开始后，不能只恢复旧 SR 注释就声称“进度双向同步”。

## 10. 弹窗设计

推荐“专注回忆”作为默认：单列内容，表达最大；揭晓后先显示释义，再显示原句，译文可折叠，笔记和概览默认收起；出处作为可点击的次要信息。答题前不展示中文答案，原句作为可主动打开的提示。

备选“语境对照”：左侧英文语境、右侧释义与译文，适合短语和上下文辨义；窄窗口自动堆叠。语境可能降低裸词回忆难度，因此作为另一种练习模式/布局，不混淆为等价测验。

建议实际弹窗：宽度 720—840px、最大不超过视口减 48px；内容阅读行宽约 60—75 个拉丁字符。表达 28—32px；释义 20—22px；原句/译文 16—18px、行高 1.6；字段间 16—24px。出处 13—14px。内容超高时只滚动正文，工具栏与底部评分区保持可见，避免整窗和正文双重滚动。

顶部只放复习范围、清楚的进度、撤销和一个关闭按钮；编辑/跳过/暂停放低强调操作区。发音复用现有能力。底部显示四个等宽但低饱和度评分按钮，只有“记得”使用主要强调色，其他按钮靠文字和键位区分，不使用四块巨大彩色区域。

未揭晓时底部只有“显示答案”；揭晓后替换为评分组。Space 只揭晓，不做默认评分；Esc 关闭且保留已提交记录。提供可见键位说明，编辑期间快捷键暂停。支持键盘焦点、屏幕阅读器状态和浅/深色主题；窄窗评分组变为 2×2。

长原句、无译文、多条例句、保存失败、等待重学和已完成状态均须验证，不能只验短文本。关闭行为由一个原生 Modal 负责，明确是否保留其默认关闭按钮，避免再出现两个 X。

## 11. 分阶段验收

A. 技术探针：在隔离工程验证锁定库、类型声明、构建、Obsidian 实际加载和四档候选状态；不改现有进度。

B. 独立预览：用结构化卡片做真实弹窗，评分只在内存模拟；先验收字号、长文本、窄屏、键盘和主题。

C. 内置复习最小版：只接收专用测试卡；完成调度、队列、日志、失败重试、撤销和重启恢复，不接管 SR 卡。

D. 迁移测试：对测试库副本执行逐卡预览、备份、解除 SR 识别、状态导入和回滚。所有验收通过后再由用户明确选择迁移实际卡片。

门槛测试：四档结果与库一致；同一操作只落一笔；保存失败不换卡；崩溃窗口可恢复；撤销可恢复到期及队列；修改释义不重置进度；跨日/DST/时钟变化正确；关闭途中无误写；重复 ID/同步冲突可见；新旧引擎无双重调度；新旧卡长内容和键盘功能通过真实 Obsidian 验收。
